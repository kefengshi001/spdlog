# 阶段 2 设计文档: 核心概念

## spdlog 架构概览

```
用户代码
  │
  ▼
Logger (日志记录器)
  │  - 持有日志级别
  │  - 管理多个 Sink
  │  - 格式化消息
  │
  ├──► Sink 1 (控制台)
  ├──► Sink 2 (文件)
  └──► Sink 3 (网络)
```

## 核心类关系

### Logger
- **职责**: 日志记录的核心入口
- **功能**: 接收日志消息、格式化、分发到所有 Sink
- **关键方法**: `trace()`, `debug()`, `info()`, `warn()`, `error()`, `critical()`
- **线程安全**: 后缀 `_mt` 表示多线程安全，`_st` 表示单线程

### Sink
- **职责**: 日志输出目标
- **功能**: 接收格式化后的消息，写入具体目标
- **类型**: stdout, stderr, 文件, 轮转文件, 系统日志, 网络等
- **特点**: 每个 Sink 可以有独立的级别和格式

### Formatter
- **职责**: 将日志消息格式化为字符串
- **语法**: pattern 语法，使用 `%` 标志
- **常用标志**: `%Y`(年), `%m`(月), `%d`(日), `%H`(时), `%M`(分), `%S`(秒), `%l`(级别), `%v`(消息), `%t`(线程)

## 日志级别

| 级别 | 值 | 用途 |
|------|-----|------|
| trace | 0 | 最详细的追踪信息 |
| debug | 1 | 调试信息 |
| info | 2 | 一般信息 |
| warn | 3 | 警告信息 |
| error | 4 | 错误信息 |
| critical | 5 | 严重错误 |
| off | 6 | 关闭所有日志 |

## 同步 vs 异步

### 同步日志
- 日志写入在调用线程完成
- 简单可靠
- 可能阻塞调用线程

### 异步日志
- 日志写入在后台线程完成
- 不阻塞调用线程
- 需要配置队列大小和线程数
- 适合高频日志场景

## 数据流

1. 用户调用 `logger->info("message")`
2. Logger 检查日志级别是否足够
3. Formatter 将消息格式化为字符串
4. Logger 将格式化后的消息发送到所有 Sink
5. Sink 将消息写入目标（控制台/文件/网络）
